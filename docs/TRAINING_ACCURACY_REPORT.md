**تحلیل:** مدل ML به دلیل نبود برچسب واقعی ناهنجاری در داده مصنوعی، ROC-AUC پایینی دارد. اما شاخص واقعی کیفیت آلارم، امتیاز انطباق EEMUA است که وضعیت بحرانی (D) را نشان می‌دهد و خود این یک یافته عملیاتی مهم است.

### ۲.۴ ماژول ۴: برآورد ریسک پویا

**الگوریتم:** XGBoost (با class balancing) + Weibull AFT + Poisson process

**داده:** مصنوعی (`data/synthetic/risk_signals.csv`) — ۴۳٬۸۰۰ رکورد (نرخ خرابی ۷.۰۵٪)

| شاخص | مقدار قبل بهبود | مقدار بعد بهبود | بهبود |
|---|---|---|---|
| **ROC-AUC** | 0.492 | **0.691** | +۴۱٪ |
| **C-index** | 0.492 | 0.691 | +۴۱٪ |
| Precision (کلاس ۱) | 0.000 | 0.175 | ✓ |
| Recall (کلاس ۱) | 0.000 | 0.336 | ✓ |
| F1 (کلاس ۱) | 0.000 | 0.230 | ✓ |
| Weighted F1 | 0.964 | 0.856 | — |

**بهبودهای اعمال‌شده:**
۱. **Class balancing:** افزودن `scale_pos_weight` برای XGBoost (وزن کلاس اقلیت = neg/pos)
۲. **بهبود داده synthetic:** تولید failure واقعاً وابسته به دما، فشار، لرزش و ساعات کار (به‌جای تصادفی)
۳. **افزایش همبستگی‌ها:** vibration 0.20، temperature 0.10 (قبلاً نزدیک صفر)

**تحلیل:** ROC-AUC=0.691 قابل قبول است اما فضای بهبود وجود دارد. با داده واقعی (DCS) که روابط قوی‌تری دارد، انتظار AUC≥0.85 می‌رود.

### ۲.۵ ماژول ۵: تشخیص خطای فرآیند (TEP) — داده واقعی

**الگوریتم:** PCA + T² (Hotelling) + SPE/Q-statistic (multivariate SPC)

**داده:** واقعی Tennessee Eastman Process (`data/real/processed/tep_train.csv` و `tep_test.csv`)

| شاخص | مقدار | توضیح |
|---|---|---|
| **avg FDR** (Fault Detection Rate) | **0.405** | میانگین نرخ تشخیص ۲۱ خطا |
| **FAR_normal** (False Alarm Rate) | **0.000** | بدون هشدار کاذب در حالت نرمال ✅ |
| Accuracy (multiclass) | 0.356 | دقت طبقه‌بندی ۲۲ کلاس |
| Weighted Precision | 0.570 | — |
| Weighted Recall | 0.544 | — |
| Weighted F1 | 0.553 | — |
| PCA Explained Variance | 0.868 | ۸۶.۸٪ واریانس با ۱۵ مؤلفه |

**تحلیل:**
- **FAR=0** ممتاز است: هیچ هشدار کاذبی در حالت نرمال صادر نمی‌شود.
- **FDR=0.41** متوسط است: حدود ۴۰٪ خطاها به‌موقع تشخیص داده می‌شوند.
- این نتایج با ادبیات علمی TEP (Yin et al. 2012) سازگار است — روش‌های PCA-based معمولاً FDR ۰.۳-۰.۶ دارند.
- برای FDR بالاتر، می‌توان از روش‌های DL (Deep Learning) مانند CNN-LSTM استفاده کرد.

| نمونه‌های خارج از spec | ۱٬۴۱�۲ | ۱۳.۳٪ از ۱۰٬۵۸۰ |
| نقض قوانین SPC | ۱۴٬۷۴۶ | شامل ۸ قانون Western Electric |
| متغیرهای کیفی پایش‌شده | ۶ | xmeas_40, 41, 09, 17, 07, 08 |
| خطاهای تحلیل‌شده | ۱۵ | از ۲۲ خطای TEP |

**تحلیل:**
- میانگین Cpk=1.0 یعنی فرآیند در حداقل قابل قبول است (هدف پتروشیمی: Cpk≥1.33).
- ۱۴٬۷۴۶ نقض قانون SPC نشان می‌دهد فرآیند کنترل آماری ضعیفی دارد.
- این ماژول تحلیلی است و شاخص‌هایش برای ارزیابی کیفیت واقعی فرآیند طراحی شده‌اند.

## ۳. بهبودهای اعمال‌شده در این نسخه

### ۳.۱ بهبود ماژول ریسک پویا (ROC-AUC: 0.49 → 0.69)

| اقدام | تأثیر |
|---|---|

- هر ۷ ماژول را آموزش می‌دهد (مصنوعی + واقعی)

## ۶. نتیجه‌گیری

این ارزیابی نشان می‌دهد که BHAM v2.1.0 با ۷ ماژول و الگوریتم‌های متنوع، چالش‌های خط تولید و کیفیت محصول پتروشیمی غدیر را به‌صورت کمّی پوشش می‌دهد. مهم‌ترین یافته‌ها:

۱. **بهترین عملکرد:** پیش‌بینی توالی (ROC-AUC=0.97) — آماده استقرار عملیاتی
۲. **بهترین بهبود:** ریسک پویا (ROC-AUC: 0.49 → 0.69، +۴۱٪) با class balancing و بهبود داده
۳. **دقت واقعی:** تشخیص خطای TEP با داده واقعی (FDR=0.41, FAR=0) — قابل قبول با فضای بهبود
۴. **یافته‌های بحرانی:** OEE بحرانی، سلامت لایه‌ها ۰.۴۷، انطباق آلارم D — نیاز به مداخله فوری

این نتایج مبنای تصمیم‌گیری برای استقرار پایلوت روی واحد اولفین پتروشیمی غدیر و مسیر ارتقا از TRL 5 به TRL 6 را فراهم می‌سازند.
